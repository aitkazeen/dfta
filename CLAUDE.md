# dfta — KursWise

Мобильный финансовый помощник. Ядро продукта: технический анализ графиков валютных пар \+ анализ новостного фона → прогноз направления → push-уведомление.

Владелец разбирается с Docker и бэкендом впервые — **объясняй решения, а не только выдавай код**.

Полная архитектура и план работ: @docs/architecture-roadmap.md

## Скоуп

- **Активы MVP:** USD, EUR, RUB, KZT. **KZT — центральная валюта продукта**, все пары котируются против неё: USD/KZT, EUR/KZT, RUB/KZT. Пар вида USD/RUB или EUR/USD (без KZT) в скоупе нет — RUB и другие валюты интересны продукту только через призму тенге. Список расширяемый, но только новыми парами X/KZT *(изменено 2026-08-07, было: 5 пар включая USD/RUB и EUR/USD)*  
- **Платформы:** iOS \+ Android одновременно  
- **Вне скоупа:** iOS-виджеты (WidgetKit), Live Activities, торговля и брокерские операции, рекомендации по акциям и облигациям, портфельные советы

## Стек

- **mobile/** — Expo (React Native), TypeScript. Запускается локально, не в Docker  
- **server/** — Fastify \+ Prisma, TypeScript, ESM. Живёт в контейнере  
- **БД** — Postgres 16 в контейнере  
- Оркестрация — Docker Compose: `compose.yaml` (база) \+ `compose.override.yaml` (локальные надстройки, подхватывается автоматически)

Появится по мере этапов, но ещё не подключено: TimescaleDB (расширение к той же Postgres, для свечей), Redis \+ BullMQ (кэш и фоновые задачи), TanStack Query \+ Zustand \+ MMKV на клиенте, Victory Native XL для графиков.

## Принятые решения

- **Expo, а не bare React Native** — чтобы не настраивать Xcode/Android Studio на старте  
- **Fastify, а не NestJS** — владелец первый раз делает бэкенд, скелет уже работает. Nest даёт DI и структуру, но добавляет три абстракции поверх той, которую ещё не пощупали. Возврат к вопросу — когда роутов станет больше и появится реальная боль от ручной сборки зависимостей  
- **Prisma, а не Drizzle** — больше документации, порог входа ниже  
- ~~**`prisma db push`, а не миграции**~~ — сделан переход на `prisma migrate dev`/`migrate deploy` 2026-08-09 (первая миграция `candle_hypertable_pk` заодно завела и `CREATE EXTENSION timescaledb` в историю миграций — раньше расширение было накатано вручную и не пережило бы `migrate reset`)  
- **Двухстадийный Dockerfile** — dev-зависимости не уезжают в финальный образ  
- **Прогноз по правилам, а не ML** — фиатные пары с управляемыми курсами (RUB, KZT) плохо предсказываются ML на малой выборке. Правила предсказуемы и отлаживаемы; ML — второй этап, за тем же интерфейсом  
- **LLM только для текста объяснения**, не для расчёта прогноза
- **Gemini, а не Anthropic, — провайдер LLM по умолчанию** (и для объяснения прогноза, и для сентимента RSS-новостей) — решение 2026-08-19. У Google AI Studio есть постоянный бесплатный тариф на Flash-моделях, у Anthropic — только разовый триал-кредит. `ANTHROPIC_API_KEY` остаётся явной платной альтернативой: обе фабрики (`explainer.factory.ts`, `news/sentiment-classifier.factory.ts`) берут Gemini, если задан `GEMINI_API_KEY`, иначе Anthropic, иначе no-op

## Текущее состояние

`Ping`/`/ping` удалены. Первая реальная вертикаль работает целиком: модели `Currency`/`CurrencyPair`/`Candle` (`Candle` пока без данных — пишущего пайплайна ещё нет), `IQuoteProvider` за фабрикой (`server/src/modules/market/`, primary НБ РК + fallback ForexRateAPI, переключение при отказе), сид трёх одобренных пар и роут `GET /v1/pairs/:id/quote`. Проверено вживую 2026-08-08: `docker compose up --build` → `npm run db:seed` → все 3 пары отдают текущий курс от НБ РК, `GBP-KZT` (не сидированная пара, вне скоупа) отдаёт 404. Также проверено, что `npm run build` (tsc) + `node dist/main.js` — путь продакшен-стадии Dockerfile — не падает на резолве относительных импортов (нужны explicit `.js`-расширения при module: ES2022 + moduleResolution: bundler).

BullMQ-воркер (`server/src/worker.ts`, отдельный контейнер `worker` в `compose.yaml`/`compose.override.yaml`) каждые 6 часов обходит активные пары через тот же `IQuoteProvider` и складывает дневные свечи в `candle` (upsert по `(pairId, timeframe, ts)` — open фиксируется первым снятием за день, high/low/close обновляются на каждом). 6 часов, а не чаще: НБ РК отдаёт один фиксинг в сутки, курс внутри дня не меняется. Проверено вживую 2026-08-09: `docker compose up --build` → воркер стартует, забирает курсы всех 3 пар от НБ РК и пишет 3 строки в `candle`.

`candle` теперь настоящая TimescaleDB hypertable (композитный PK `(pairId, timeframe, ts)` вместо отдельного `id`, миграция `candle_hypertable_pk`), схема перешла с `db push` на `prisma migrate dev`/`migrate deploy` — проверено вживую 2026-08-09.

**2026-08-19/20/23 — новостной модуль (этап 3 роадмапа).** `server/src/modules/news/`: `INewsSource` за фабрикой (`sources.factory.ts`) — `NbkRssSource` (`nationalbank.kz/rss_news_russian.xml`, обязателен, без ключа) + `MarketauxSource` (нужен `MARKETAUXAPI_KEY`, опционален, source отдаёт entities с валютными тегами напрямую). `SentimentClassifier` за фабрикой (`sentiment-classifier.factory.ts`, тот же Gemini/Anthropic/no-op выбор, что у explainer) классифицирует батчем RSS-статьи без готового сентимента; у Marketaux сентимент уже готов, LLM не зовётся. Пайплайн (`pipeline.ts`) — дедуп дублей между источниками (`dedup.ts`, сравнение заголовков + временное окно, канонической считается статья с более высоким `sourceWeight`), фильтр релевантности по паре (Marketaux — по entities, RSS — по ключевым словам `relevanceKeywords` в `config.ts`), `impactScore = sourceWeight × freshness(halfLife 12ч)`, запись в `news_article`/`news_pair_link`. `getNewsScore` (`repository.ts`) — взвешенное среднее `our_sentiment`/`raw_sentiment` за 24ч с весом `impactScore`, 0 если новостей за окно не было. Воркер (`collectNews` в `worker.ts`) гоняет пайплайн каждые 15 минут, отдельный от опроса котировок (6ч) BullMQ job scheduler `collect-news`. `RulesForecastEngine` теперь получает `newsScore` по-настоящему (`worker.ts:maybeGenerateForecast` зовёт `getNewsScore` перед `predict()`) — слияние `technicalScore * 0.6 + newsScore * 0.4` (roadmap §5.3) больше не теоретическое, а вычисляется на реальных данных.

**2026-08-23 — два живых бага найдены и исправлены при проверке новостного пайплайна.** (1) `GEMINI_API_KEY` в корневом `.env` оказался токеном не того типа (формат `AQ.Ab8...`, не `AIzaSy...` — AI Studio отвечал `401 ACCESS_TOKEN_TYPE_UNSUPPORTED`); из-за no-op-дизайна фабрик это не роняло пайплайн, а тихо резало RSS-статьи без сентимента (`pipeline.ts`: `if (sentiment === undefined) continue` — статья не пишется вообще, не просто получает нейтральный скор) и объяснения прогнозов. Ключ заменён, проверено вживую прямым вызовом Gemini API и живым прогоном воркера. (2) НБ РК отдаёт `rss_news_russian.xml`, но описания в нём фактически на казахском — `relevanceKeywords` в `news/config.ts` были только на русском/английском, поэтому все 10 статей RSS в тестовом прогоне отсеивались до сентимент-классификации. Добавлено казахское `еуро` (доллар/рубль/теңге совпадают в написании с русским) — не полное решение (казахоязычные RSS-новости на другие темы вообще могут не содержать релевантных ключевых слов), но закрывает конкретно найденный разрыв.

**2026-08-23 — калибровка confidence (правило 6, этап 4 роадмапа).** `server/scripts/backtest-forecast.ts` — walk-forward бэктест `RulesForecastEngine` по 2-летнему датасету НБ РК, уже забэкфилленному в `candle` (`npm run fx:backfill-dataset`, 738 дневных свечей × 3 пары). Идёт день за днём по каждой паре, вызывает `predict()` с indicators, посчитанными только по свечам до текущего дня (честный walk-forward, без заглядывания вперёд), сверяет direction с `resolveForecastOutcome` на факте через 24ч/7д. **Важное упрощение:** `newsScore = 0` для всей истории — двухлетнего архива новостей не существует (новостной пайплайн запущен только в 2026-08), калибровка отражает фактически только technicalScore-часть блендинга. Результат бинуется по децилям сырого `|blendedScore|`, прогоняется через isotonic regression (pool-adjacent-violators — гарантирует, что confidence не падает с ростом скора) → `server/src/modules/forecast/calibration.ts` (генерируемый файл, `npm run forecast:backtest` перезаписывает). `RulesForecastEngine.predict()` теперь берёт `confidence` из `calibrateConfidence(rawScore, horizon)`, не из `Math.abs(blendedScore)` напрямую.

**Находка бэктеста — точность прогноза близка к случайной.** Для горизонта 24ч реальный hit rate по всем бакетам скора — 27–40% (ниже, чем ~33% у случайного угадывания между up/down/flat), калиброванная confidence не превышает ~0.35. Для 7д лучше (50–54% при score ≥0.1), но нижний бакет (score < 0.1) даёт всего 7.8%. Это эмпирическое подтверждение риска, который роадмап называл гипотетическим (§10: «Точность прогноза окажется около случайной — Высокая [вероятность]»). Не исправлено — подбор весов (roadmap §9, этап 4: «подбор весов») ещё предстоит; также стоит проверить, не искажают ли range-индикаторы (ATR, Stochastic) сигнал из-за того, что НБ РК даёт одну дневную фиксацию (open=high=low=close), а не внутридневной диапазон.

## Что важно помнить

- **`DATABASE_URL` использует хост `db`**, не `localhost` — это имя сервиса в сети Compose. В `.env.example` для запуска без Docker стоит `localhost` — так и задумано  
- **Fastify слушает `0.0.0.0`** — обязательно внутри контейнера  
- **Адрес бэкенда в приложении вычисляется автоматически** в `mobile/src/api.ts` из `Constants.expoConfig.hostUri`. Не хардкодь туда IP  
- **npm 12 сломает этот проект** — он отключает postinstall-скрипты, на которых держатся Prisma, esbuild и нативные модули RN. Владелец сидит на npm 10.9 сознательно, не предлагай обновляться без разговора  
- **В `server/` может лежать лишний `node_modules`** — артефакт сборки, на образ не влияет (отсекается `.dockerignore`)  
- **Секреты только в `.env`**, никогда в репозитории. Сейчас там `GEMINI_API_KEY` и `MARKETAUXAPI_KEY` (оба опциональны — фабрики уходят в no-op без ключа, см. «Принятые решения»)

## Архитектурные правила — не нарушать

1. **Все внешние источники — за интерфейсом.** `IQuoteProvider`, `INewsProvider`. Каждый: primary \+ 1–2 fallback, переключение при отказе. Бизнес-логика никогда не зовёт провайдера напрямую и не знает, откуда пришли данные. Без Nest-овского DI это делается фабрикой, выбирающей реализацию по конфигу — просто и явно  
2. **Прогнозный движок — за интерфейсом `ForecastEngine`** (`predict(input): Promise<ForecastResult>`, `readonly version: string`). v1 \= `RulesForecastEngine`. v2 \= `MlForecastEngine` позже. Замена движка не должна трогать приложение  
3. **LLM вызывается ТОЛЬКО для генерации текста объяснения** по уже посчитанным числам. Никогда — для расчёта самого прогноза. Результат должен быть воспроизводимым. Кэш по хэшу входа  
4. **Веса индикаторов и пороги — в конфиге, не в коде**  
5. **`forecast_outcome` пишется всегда.** Каждый прогноз по истечении горизонта резолвится фактом. Без этого нельзя ни показать честную точность, ни сравнить движки  
6. **`confidence` берётся из калиброванной таблицы** «скор → фактическая частота попадания» на walk-forward бэктесте (2+ года), не из формулы наугад  
7. **`/v1/pairs/snapshot` отдаётся из кэша.** Главный экран не делает N запросов по числу пар в watchlist  
8. **Каждый внешний вызов — с таймаутом и ретраем.** Провайдер данных упадёт, это вопрос времени

## Прогнозный пайплайн

- `technicalScore ∈ [−1, +1]`: EMA20/50/200 \+ наклон, RSI(14), MACD(12,26,9), Stochastic, ATR(14), ширина Боллинджера, локальные экстремумы 30/90д. Считается на каждой свече, кэшируется в `indicator_value`  
- `newsScore ∈ [−1, +1]`: дедуп (URL-хэш \+ эмбеддинг заголовка) → фильтр релевантности по сущностям → сентимент (Marketaux где есть, LLM-классификация батчем для локальных RSS) → `impact_score` \= источник × свежесть × релевантность → взвешенное среднее за 24ч с экспоненциальным затуханием  
- Слияние v1: `technicalScore * 0.6 + newsScore * 0.4`, далее калибровка  
- Частота: 1 прогноз в сутки на пару (утро) \+ внеплановый при резком движении или важной новости

## Юридические ограничения — критично

- **Никаких инвестиционных рекомендаций.** Формулировки: «вероятное направление», «аналитический сигнал». Никогда — «покупайте», «продавайте», «стоит войти». Показываем: направление \+ вероятность \+ горизонт \+ 3 причины  
- **Никаких персональных рекомендаций по инструментам** (акции, облигации, портфель). В РФ это инвестиционное консультирование (СРО \+ реестр ЦБ), в РК — лицензия АРРФР. Обезличенная аналитика допустима, персональная — нет  
- **Никаких кнопок исполнения сделок и интеграций с брокером** — иначе Apple требует подачу приложения лицензированной финансовой организацией  
- **Дисклеймеры** на онбординге и на экране прогноза. **Раскрытие использования ИИ** \+ согласие на передачу данных третьим сторонам  
- **Точность показываем реальную**, из `forecast_outcome`, не маркетинговую  
- Privacy Manifest (`PrivacyInfo.xcprivacy`) \+ Google Play Data Safety обязательны

## Уведомления
