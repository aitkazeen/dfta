# dfta — KursWise

Мобильный финансовый помощник. Ядро продукта: технический анализ графиков валютных пар \+ анализ новостного фона → прогноз направления → push-уведомление.

Владелец разбирается с Docker и бэкендом впервые — **объясняй решения, а не только выдавай код**.

Полная архитектура и план работ: @docs/architecture-roadmap.md

## Скоуп

- **Активы MVP:** USD, EUR, RUB, KZT. **KZT — центральная валюта продукта**, все пары котируются против неё: USD/KZT, EUR/KZT, RUB/KZT. Пар вида USD/RUB или EUR/USD (без KZT) в скоупе нет — RUB и другие валюты интересны продукту только через призму тенге. Список расширяемый, но только новыми парами X/KZT *(изменено 2026-08-07, было: 5 пар включая USD/RUB и EUR/USD)*  
- **Платформы:** iOS \+ Android одновременно  
- **Вне скоупа:** iOS-виджеты (WidgetKit), Live Activities, торговля и брокерские операции, рекомендации по акциям и облигациям, портфельные советы

## Стек

- **mobile/** — Expo (React Native), TypeScript. Запускается локально, не в Docker  
- **server/** — Fastify \+ Prisma, TypeScript, ESM. Живёт в контейнере  
- **БД** — Postgres 16 в контейнере  
- Оркестрация — Docker Compose: `compose.yaml` (база) \+ `compose.override.yaml` (локальные надстройки, подхватывается автоматически)

Появится по мере этапов, но ещё не подключено: TimescaleDB (расширение к той же Postgres, для свечей), Redis \+ BullMQ (кэш и фоновые задачи), TanStack Query \+ Zustand \+ MMKV на клиенте, Victory Native XL для графиков.

## Принятые решения

- **Expo, а не bare React Native** — чтобы не настраивать Xcode/Android Studio на старте  
- **Fastify, а не NestJS** — владелец первый раз делает бэкенд, скелет уже работает. Nest даёт DI и структуру, но добавляет три абстракции поверх той, которую ещё не пощупали. Возврат к вопросу — когда роутов станет больше и появится реальная боль от ручной сборки зависимостей  
- **Prisma, а не Drizzle** — больше документации, порог входа ниже  
- ~~**`prisma db push`, а не миграции**~~ — сделан переход на `prisma migrate dev`/`migrate deploy` 2026-08-09 (первая миграция `candle_hypertable_pk` заодно завела и `CREATE EXTENSION timescaledb` в историю миграций — раньше расширение было накатано вручную и не пережило бы `migrate reset`)  
- **Двухстадийный Dockerfile** — dev-зависимости не уезжают в финальный образ  
- **Прогноз по правилам, а не ML** — фиатные пары с управляемыми курсами (RUB, KZT) плохо предсказываются ML на малой выборке. Правила предсказуемы и отлаживаемы; ML — второй этап, за тем же интерфейсом  
- **LLM только для текста объяснения**, не для расчёта прогноза

## Как запускать

docker compose up \--build      \# бэкенд \+ база, из корня

cd mobile && npx expo start    \# приложение, отдельный терминал

Проверка бэкенда: [http://localhost:3000/health](http://localhost:3000/health)

## Что важно помнить

- **`DATABASE_URL` использует хост `db`**, не `localhost` — это имя сервиса в сети Compose. В `.env.example` для запуска без Docker стоит `localhost` — так и задумано  
- **Fastify слушает `0.0.0.0`** — обязательно внутри контейнера  
- **Адрес бэкенда в приложении вычисляется автоматически** в `mobile/src/api.ts` из `Constants.expoConfig.hostUri`. Не хардкодь туда IP  
- **npm 12 сломает этот проект** — он отключает postinstall-скрипты, на которых держатся Prisma, esbuild и нативные модули RN. Владелец сидит на npm 10.9 сознательно, не предлагай обновляться без разговора  
- **В `server/` может лежать лишний `node_modules`** — артефакт сборки, на образ не влияет (отсекается `.dockerignore`)  
- **Секреты только в `.env`**, никогда в репозитории. Скоро там будут ключи FX-провайдера, Marketaux и LLM

## Архитектурные правила — не нарушать

1. **Все внешние источники — за интерфейсом.** `IQuoteProvider`, `INewsProvider`. Каждый: primary \+ 1–2 fallback, переключение при отказе. Бизнес-логика никогда не зовёт провайдера напрямую и не знает, откуда пришли данные. Без Nest-овского DI это делается фабрикой, выбирающей реализацию по конфигу — просто и явно  
2. **Прогнозный движок — за интерфейсом `ForecastEngine`** (`predict(input): Promise<ForecastResult>`, `readonly version: string`). v1 \= `RulesForecastEngine`. v2 \= `MlForecastEngine` позже. Замена движка не должна трогать приложение  
3. **LLM вызывается ТОЛЬКО для генерации текста объяснения** по уже посчитанным числам. Никогда — для расчёта самого прогноза. Результат должен быть воспроизводимым. Кэш по хэшу входа  
4. **Веса индикаторов и пороги — в конфиге, не в коде**  
5. **`forecast_outcome` пишется всегда.** Каждый прогноз по истечении горизонта резолвится фактом. Без этого нельзя ни показать честную точность, ни сравнить движки  
6. **`confidence` берётся из калиброванной таблицы** «скор → фактическая частота попадания» на walk-forward бэктесте (2+ года), не из формулы наугад  
7. **`/v1/pairs/snapshot` отдаётся из кэша.** Главный экран не делает N запросов по числу пар в watchlist  
8. **Каждый внешний вызов — с таймаутом и ретраем.** Провайдер данных упадёт, это вопрос времени

## Прогнозный пайплайн

- `technicalScore ∈ [−1, +1]`: EMA20/50/200 \+ наклон, RSI(14), MACD(12,26,9), Stochastic, ATR(14), ширина Боллинджера, локальные экстремумы 30/90д. Считается на каждой свече, кэшируется в `indicator_value`  
- `newsScore ∈ [−1, +1]`: дедуп (URL-хэш \+ эмбеддинг заголовка) → фильтр релевантности по сущностям → сентимент (Marketaux где есть, LLM-классификация батчем для локальных RSS) → `impact_score` \= источник × свежесть × релевантность → взвешенное среднее за 24ч с экспоненциальным затуханием  
- Слияние v1: `technicalScore * 0.6 + newsScore * 0.4`, далее калибровка  
- Частота: 1 прогноз в сутки на пару (утро) \+ внеплановый при резком движении или важной новости

Скрипт: `server/scripts/export-nbk-dataset.ts` → `server/data/nbk-rates-2y.csv` (в `.gitignore`, регенерируется)  
  + платные провайдеры (кандидаты: ForexRateAPI, UniRateAPI, exchangeratesapi.io, Twelve Data) остаются на роль **live/intraday-источника** в будущем `IQuoteProvider` — там 30-дневное окно free-тира не мешает. Выбор конкретного live-провайдера ещё не сделан. Frankfurter не годится ни для одной пары MVP (KZT не поддерживает, а EUR/USD без KZT вне скоупа) — см. architecture-roadmap.md §3.1  
- **Новости:** Marketaux (глобальный фон, готовый sentiment) \+ собственный RSS-коллектор: ЦБ РФ, НБ РК, Минфин, Interfax, KASE. Проверено вживую: `countries=kz` у Marketaux даёт 0 результатов — казахстанских источников там нет, RSS-коллектор НБ РК/KASE обязателен, не опционален (детали — architecture-roadmap.md §3.2)  
- **Запрещённые источники:** Investing.com (нет публичного API, T\&C прямо запрещают использование их данных в сервисах) и TradingView (только iframe-виджеты, непригодны для RN). Не предлагать их  
- **Макро-календарь:** для MVP — ручной seed-справочник дат заседаний ЦБ РФ / НБ РК / ФРС / ЕЦБ

## Юридические ограничения — критично

- **Никаких инвестиционных рекомендаций.** Формулировки: «вероятное направление», «аналитический сигнал». Никогда — «покупайте», «продавайте», «стоит войти». Показываем: направление \+ вероятность \+ горизонт \+ 3 причины  
- **Никаких персональных рекомендаций по инструментам** (акции, облигации, портфель). В РФ это инвестиционное консультирование (СРО \+ реестр ЦБ), в РК — лицензия АРРФР. Обезличенная аналитика допустима, персональная — нет  
- **Никаких кнопок исполнения сделок и интеграций с брокером** — иначе Apple требует подачу приложения лицензированной финансовой организацией  
- **Дисклеймеры** на онбординге и на экране прогноза. **Раскрытие использования ИИ** \+ согласие на передачу данных третьим сторонам  
- **Точность показываем реальную**, из `forecast_outcome`, не маркетинговую  
- Privacy Manifest (`PrivacyInfo.xcprivacy`) \+ Google Play Data Safety обязательны
