# dfta — скелет «мобилка + бэкенд»

Expo (React Native) → Fastify → Postgres. Бэкенд и база живут в Docker,
приложение запускается на телефоне и ходит на них по сети.

```
┌─────────────────┐   HTTP    ┌──────────────┐          ┌────────────┐
│  Expo-приложение│ ────────► │  api :3000   │ ───────► │  db :5432  │
│   на телефоне   │           │   Fastify    │  Prisma  │  Postgres  │
└─────────────────┘           └──────────────┘          └────────────┘
       твоя машина            └────── docker compose ──────┘
```

## Что нужно поставить

- Docker Desktop
- Node.js 20+
- На телефон — приложение **Expo Go** (App Store / Google Play)

Xcode и Android Studio на старте не нужны.

## Запуск

**Шаг 1. Бэкенд и база.** Из корня проекта:

```bash
docker compose up --build
```

Первый раз это займёт пару минут — качаются образы. Готово, когда в логах
появится `Server listening at http://0.0.0.0:3000`.

Проверь из браузера: <http://localhost:3000/health> — должен вернуться JSON.

**Шаг 2. Приложение.** В другом терминале:

```bash
cd mobile
npm install
npx expo start
```

Сканируешь QR-код камерой (iOS) или из Expo Go (Android). Жмёшь в приложении
кнопку — если пришёл `pong`, вся цепочка работает.

Телефон и компьютер должны быть в одной Wi-Fi сети.

## Что где лежит

```
dfta/

├── compose.override.yaml   # локальные надстройки, подхватывается сам

│   ├── financer-design-brief.md  # дизайн-бриф: продукт, дизайн-система, все экраны

├── server/
│   ├── Dockerfile          # двухстадийная сборка образа
│   ├── .dockerignore       # без него в образ уедет твой node_modules
│   ├── prisma/schema.prisma# описание таблиц
│   └── src/main.ts         # роуты Fastify
└── mobile/
    ├── App.tsx             # единственный экран
    └── src/api.ts          # вычисление адреса бэкенда
```

## Дизайн

Дизайн-бриф — `docs/financer-design-brief.md`: продукт, аудитория, дизайн-система (цвета, типографика, компоненты), спецификация экранов, юридические и accessibility-требования. Основной источник правды при вёрстке UI.

Готовые макеты конкретных экранов (высокая точность, HTML-референсы, не production-код) — `docs/design-handoffs/`. На сейчас там экран пары (4.3, с построчным описанием в `HANDOFF-4.3.md`), watchlist (4.2) и полный прогноз (4.4). Открывать `.dc.html`-файлы прямо в браузере, пересоздавать в `mobile/` на Expo/React Native по паттернам, уже принятым в кодовой базе.

## Ежедневные команды

```bash
docker compose up              # поднять
docker compose up --build      # поднять с пересборкой образа
docker compose logs -f api     # смотреть логи бэкенда
docker compose exec api sh     # зайти внутрь контейнера
docker compose down            # остановить
docker compose down -v         # остановить и стереть данные БД
```

Правки в `server/src/**` подхватываются на лету — пересобирать не надо.
Пересборка нужна только когда поменялся `package.json` или `Dockerfile`.

## Работа с базой

Схема описывается в `server/prisma/schema.prisma`. После правки:

```bash
docker compose exec api npx prisma db push
```

`db push` просто приводит таблицы в соответствие со схемой — удобно, пока
структура ещё меняется каждый час. Когда устаканится, переходи на миграции
(`prisma migrate dev`): они сохраняют историю изменений в файлы, которые
едут в git и накатываются на проде.

Посмотреть данные глазами:

```bash
docker compose exec api npx prisma studio
```

Или подключись любым GUI (DBeaver, TablePlus) на `localhost:5432`,
пользователь `app`, пароль `secret`.

## Если что-то не работает

**Приложение пишет «Network request failed».** Почти всегда — адрес.
Посмотри, какой URL показан под заголовком в приложении, и открой его
в браузере телефона. Не открывается — телефон не в той сети, либо
файрвол компьютера рубит входящие на 3000.

**`port is already allocated`.** Порт 3000 или 5432 занят другим процессом.
Либо погаси его, либо поменяй левое число в `ports` — например `"3001:3000"`.

**api падает с ошибкой подключения к БД.** Убедись, что в `DATABASE_URL`
хост `db`, а не `localhost`. Внутри контейнера localhost — это он сам.

**Поменял package.json, а изменений нет.** Нужна пересборка:
`docker compose up --build`.

**Всё сломалось непонятно как.** Ядерный вариант — снести и поднять заново:

```bash
docker compose down -v
docker compose up --build
```

Данные в базе при этом теряются.

## Git

К Docker отношения не имеет, но пригодится сразу:

```bash
git init
git add .
git commit -m "первый скелет"
```

`.gitignore` уже настроен — `node_modules`, `dist` и `.env` в репозиторий
не попадут. Секреты в git не коммитят никогда: сейчас пароль `secret`
лежит прямо в `compose.yaml`, и для локальной песочницы это нормально,
но перед выкладкой куда-либо его выносят в `.env`.

## Куда дальше

1. Добавь свои модели в `schema.prisma` вместо `Ping`
2. Опиши роуты в `server/src/` — разнеси по файлам, когда их станет больше пяти
3. В приложении добавь навигацию (`expo-router`) и работу с запросами
   (`@tanstack/react-query` — кеш, повторы, состояния загрузки из коробки)
4. Понадобится фоновая обработка или другой язык — это ещё один сервис
   в `compose.yaml` со своим Dockerfile, обращение по имени сервиса
